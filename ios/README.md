# Ballet Diary — iOS app

SwiftUI app for iPhone (and iPad), built for iOS 26's Liquid Glass. Diary pages are stored on the device with SwiftData. The Python backend is **optional**: the app works fully offline and only talks to the server when you tap *Sync now*.

```
ios/
├── BalletDairy.xcodeproj
└── BalletDairy/
    ├── App/              BalletDairyApp.swift: app entry + tab bar
    ├── Design/           Theme (colours, type), HandDrawn (doodles, paper), Components (glass chips, cards…)
    ├── Models/           DiaryEntry (SwiftData), Movement catalogue, Stats
    ├── Features/
    │   ├── Diary/        home page, week strip, movement picker, PencilKit sketches
    │   ├── Calendar/     month grid, stats tiles, charts
    │   ├── Library/      répertoire grid, movement detail
    │   ├── Dancer/       Skeleton (kinematics + animator), DancerStageView (3D), PoseSketch (2D)
    │   └── Settings/
    ├── Services/         APIClient + sync, sample data
    ├── Resources/        movements.json, poses.json (generated by backend/scripts)
    └── Assets.xcassets   app icon, accent colour
```

## Requirements

- A Mac with **Xcode 26 or newer** (Mac App Store). iOS 26 is the first iOS with the Liquid Glass APIs the app uses.
- An iOS 26+ simulator (Xcode installs one), or an iPhone on iOS 26+.
- No CocoaPods or Swift packages. Everything is Apple frameworks (SwiftUI, SwiftData, SceneKit, PencilKit, Charts).

## Run in the Simulator

1. Open `ios/BalletDairy.xcodeproj` (double-click, or `open ios/BalletDairy.xcodeproj`).
2. In the toolbar, choose the **BalletDairy** scheme and a simulator, e.g. *iPhone 17 Pro*.
3. Press **⌘R**.

The Simulator doesn't need signing. If Xcode asks for a team anyway, do step 2 of the next section.

**See it with data:** a fresh install has an empty diary. Tap **⚙︎** (top right of the Diary tab) → **Fill the last six weeks with sample practice** to bring the calendar and charts to life. **Erase all diary pages** in the same screen resets it.

## Run on your iPhone

1. Connect the iPhone with a cable (or pair over Wi-Fi in *Window → Devices and Simulators*).
2. In Xcode, select the **BalletDairy** project → **BalletDairy** target → **Signing & Capabilities**:
   - tick **Automatically manage signing**
   - **Team**: your Apple ID ("Personal Team" works for free; *Xcode → Settings → Accounts* to add one)
   - if Xcode says the bundle ID is taken, change `com.katefu.BalletDiary` to something unique
3. Pick your iPhone as the run destination and press **⌘R**.
4. First time only, on the iPhone:
   - turn on **Settings → Privacy & Security → Developer Mode** (the phone restarts)
   - if the app won't open: **Settings → General → VPN & Device Management** → trust your developer certificate

With a free Personal Team, the app expires after 7 days. Just run it from Xcode again.

## Connect to the backend (optional)

1. Start the server. See [`../backend/README.md`](../backend/README.md).
2. In the app: **⚙︎ → Backup & sync → Server**
   - Simulator: `http://127.0.0.1:8000` (already the default)
   - iPhone: `http://<your Mac's IP>:8000`, with the server started using `--host 0.0.0.0`
3. Tap **Sync now**. Allow *Local Network* access when iOS asks.

## Previews

`App/BalletDairyApp.swift` has a `#Preview` of the whole app with an in-memory database. Open the file and show the canvas with **⌥⌘↩**. The 3D stage is SceneKit, so it animates best in the Simulator rather than the canvas.

## Changing things

- **Colours, fonts:** `Design/Theme.swift`. The 9 category colours were checked for colour-blind separation, so keep that order if you swap shades.
- **Doodles** (bow, hearts, wobbly circles, paper): `Design/HandDrawn.swift`.
- **Movements & 3D poses:** don't edit the JSON in `Resources/`. Edit `backend/scripts/build_movements.py` / `build_poses.py` and regenerate (see the backend README); both copies update together.
- **New Swift files:** create them anywhere under `ios/BalletDairy/`. The project uses Xcode's synchronized folders, so they're added to the app automatically.

## Troubleshooting

- **"Failed to find a valid device" / no iOS 26 simulator**: *Xcode → Settings → Components* and download the iOS 26 platform.
- **Signing errors**: re-select your Team in *Signing & Capabilities*, and make the bundle identifier unique.
- **Build errors after pulling new code**: *Product → Clean Build Folder* (⇧⌘K) and build again. If it persists, send the error text.
- **App crashes on launch after a data-model change**: delete the app from the simulator or phone (it resets the local SwiftData store) and run again.
- **Sync fails**: check the server is running (`curl http://127.0.0.1:8000/health` on the Mac) and the address in Settings includes `http://` and `:8000`.
